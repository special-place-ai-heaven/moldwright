# Test skills before changing agent architecture

**Decision: test whether a skill is selected and whether it improves the finished task before changing coworker roles.** A skill loading is not proof that it helped; a missed load is not proof that its instructions are ineffective. The strongest of this report's research candidates is a small, paired, non-production replay with explicit requests, ambiguous requests and negative controls, judged on actual task correctness. This ranking does not reorder the existing factory work queue. Keep independent factory checks and required rules and permissions intact. This is a research recommendation, not a measured Moldwright improvement. The repository references below are pinned to `dev` commit `fbf058d1770afdfa4f81d2e47162a8908c0ba7d6`; the bounded review did not establish whether a general skill-outcome bench or general ADR lookup exists elsewhere.

## 1. Separate skill activation from task outcomes

**First research candidate: adapt the proposed fixed-replay method to one representative skill.** At the baseline, [`buildSkillIndex`](https://github.com/special-place-ai-heaven/moldwright/blob/fbf058d1770afdfa4f81d2e47162a8908c0ba7d6/apps/engine/src/skills/index.ts#L5-L10) filters disabled skills and supplies names, slugs and descriptions; [`index.test.ts`](https://github.com/special-place-ai-heaven/moldwright/blob/fbf058d1770afdfa4f81d2e47162a8908c0ba7d6/apps/engine/src/skills/index.test.ts#L12-L25) exercises the index. [`skill_read` and `skill_read_file`](https://github.com/special-place-ai-heaven/moldwright/blob/fbf058d1770afdfa4f81d2e47162a8908c0ba7d6/apps/engine/src/tools/builtin/skills.ts#L50-L81) expose the procedure and requested reference files. The [system prompt](https://github.com/special-place-ai-heaven/moldwright/blob/fbf058d1770afdfa4f81d2e47162a8908c0ba7d6/apps/engine/src/agents/systemPrompt.ts#L271) conditionally includes the index; its [skill-writing guidance](https://github.com/special-place-ai-heaven/moldwright/blob/fbf058d1770afdfa4f81d2e47162a8908c0ba7d6/apps/engine/src/agents/systemPrompt.ts#L104) and [`skill_propose`](https://github.com/special-place-ai-heaven/moldwright/blob/fbf058d1770afdfa4f81d2e47162a8908c0ba7d6/apps/engine/src/tools/builtin/skill-propose.ts#L50-L55) preserve user approval. These are mechanisms, not a model-level outcome measurement.

Pin the same model, skill version, starting fixture, environment and task rubric for paired runs. Include explicit skill requests, plausible ambiguous requests, and unrelated no-match tasks where loading is wrong. Record whether the intended skill was read, missed or wrongly read. Compare normal routing with a forced load to distinguish discovery from the procedure's effect, and with that **one non-required skill** disabled to test its contribution; do not disable required rules or permissions. Judge completed artifacts and forbidden outcomes blind to configuration, retaining per-task failures; time and cost are optional secondary measures. For a small starting sample, repeat each matched case at least twice and report individual outcomes rather than claiming statistical proof.

**Accept** a routing or content change only if relevant task correctness improves without new forbidden outcomes or false activations; **stop** if results are mixed or too few to support a decision; **disqualify** any version that bypasses permissions, required rules or an independent check. This adapts the method of the [factory-only fixed-replay proposal](../2026-11-19-borrowed-ideas/IDEAS.md#16-a-small-fixed-replay-set-later), not an existing shared implementation or bench. That proposal is last in the earlier [order of work](../2026-11-19-borrowed-ideas/IDEAS.md#order-of-work); this report does not reorder it. The [template bench](https://github.com/special-place-ai-heaven/moldwright/blob/fbf058d1770afdfa4f81d2e47162a8908c0ba7d6/.claude/skills/create-agent-template/references/benchmark.md#L1-L16) tests specific customer-dropoff scenarios for template capture; it is not evidence of a general skill evaluation.

## 2. Retrieve decisions without turning them into skills

**Second candidate: test one decision-retrieval case against the repository's existing records, not a new database.** An ADR records a decision and its rationale; a skill packages a procedure, optionally with scripts and references. They can refer to each other but are not substitutes ([Nygard](https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions); [Agent Skills specification](https://agentskills.io/specification#directory-structure)). Moldwright already has a [factory decisions table](https://github.com/special-place-ai-heaven/moldwright/blob/fbf058d1770afdfa4f81d2e47162a8908c0ba7d6/tools/factory/DECISIONS.md#L1-L6) and [tests for its structure and in-force wording](https://github.com/special-place-ai-heaven/moldwright/blob/fbf058d1770afdfa4f81d2e47162a8908c0ba7d6/tools/factory/test_decisions.py#L18-L47). The [planner brief](https://github.com/special-place-ai-heaven/moldwright/blob/fbf058d1770afdfa4f81d2e47162a8908c0ba7d6/tools/factory/planning.py#L296) already asks for current code and verified decisions.

Use a pinned, isolated fixture containing a current artifact and an explicitly superseded record. Give the same decision-dependent task to the same model with ordinary repository lookup and with a narrowly linked relevant record. Blind-grade whether the answer identifies the current decision, cites the artifact and correctly treats the older record as historical. **Accept** only demonstrably better correctness, or equal correctness with a predeclared useful benefit such as less lookup time, and no regression on controls or missed asks. **Keep the baseline** on a tie or an inconclusive small sample; **disqualify** advice that applies the superseded decision or overrides current required controls. Do not infer that no broader ADR retrieval exists from this bounded review.

## 3. Test worker continuity without removing independent checks

**Third research candidate: scoped replay of one worker handoff**, after the first two candidates have useful results if these research trials are undertaken. Compare a worker continuing the same bounded task with a fresh worker receiving the existing handover, while keeping the same independent factory check in both arms. The [context capture](https://github.com/special-place-ai-heaven/moldwright/blob/fbf058d1770afdfa4f81d2e47162a8908c0ba7d6/apps/engine/src/agents/claude-context.ts#L52-L105) already records occupancy and compaction hooks; the earlier [handover design and measurements](../2026-11-18-context-economy/HANDOVER.md#what-is-measured) already propose measuring resumed work. Pin starting state, model, task and checker; blind-grade completion, missed asks and forbidden outcomes, with rework and cost secondary. **Accept** only demonstrably better correctness, or equal correctness with a predeclared useful benefit such as less rework, and no regression on controls or missed asks. **Keep the baseline** on a tie or an inconclusive small sample; **disqualify** loss of an independent check or permission boundary. This is not a proposal to remove coworker roles.

## Evidence favors bounded comparisons, not a universal architecture

Anthropic's support-desk [returns-fold run](https://github.com/anthropics/single-agent-loop-kit/blob/release/examples/support-desk/example-run/README.md) used 12 tasks, two repetitions and 24 graded rows per side. Calculated from its published [baseline](https://github.com/anthropics/single-agent-loop-kit/blob/c43796287b83bec847db923f07131d1cc8de750d/examples/support-desk/example-run/results/baseline/results.jsonl) and [folded](https://github.com/anthropics/single-agent-loop-kit/blob/c43796287b83bec847db923f07131d1cc8de750d/examples/support-desk/example-run/results/v1/results.jsonl) logs, `grade.task_complete` rose from **22/24 to 23/24**, while median `latency_s` fell from **25.675 to 15.07**. The aggregate hides a new regression: t11 improved from 0/2 to 2/2 while t01 fell from 2/2 to 1/2. The figures were recalculated here from the published logs; the models were not rerun. The [guide](https://claude.com/resources/articles/building-agents-when-to-fold-subagents-into-your-main-agent-loop) describes the skipped shipping delivery-date check. Forbidden returns and an account-to-returns chain were missing, and no with/without-skills comparison was completed. A separate diagnostics-as-tool run used a different 17-task baseline and was not a completed single loop ([run record](https://github.com/anthropics/single-agent-loop-kit/blob/release/examples/support-desk/example-run/as-tool/README.md)). These small experiments justify checking whole tasks and bad outcomes, not projecting a speedup. Anthropic's [context-engineering article](https://claude.dev/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models/) and migration guide describe over 80% fewer **initial instructions**; prompt length alone does not establish cost or task quality.

In Anthropic's [hidden-profile experiment](https://www.anthropic.com/research/multiagent-systems#epistemic-failures), four agents held distributed facts and voted; reported group accuracy varied substantially by model under that task. Its separately designed conflicting-migration experiment imposed mutually incompatible goals. Neither proves that one agent is always better or identifies a single cause of coordination failure. Preserve the value of independent checking while testing whether particular handoffs lose necessary context.

The video recommends capturing repeatable work and comparing with and without a skill, but its animation and wildcard examples are anecdotes without a stated controlled baseline ([video, 13:38](https://www.youtube.com/watch?v=IMSYKloMFrE&t=818s)). Vendor claims of ROI, universal agents and automatic compliance in the OutcomeOps articles lack supporting primary methods in the recovered text; they are not grounds for a Moldwright change. A changed file tree is likewise not proof of correctness or causation.
